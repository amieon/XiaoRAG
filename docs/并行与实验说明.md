# 并行与实验说明

## 1. 两条并行轴

### CPU：文档级并行

`run_folder()` 使用线程池同时处理多个文件。并行的部分包括文件哈希、压缩包解包、Office/PDF 渲染、原生文本/表格抽取、页包生成、最终 IR 写出，以及启用时的知识单元构建。知识单元构建不加载模型，独立离线入口 `build_knowledge_units.py` 也支持按文档进行 CPU 线程并行。每个文件有独立输出目录，因此不需要全局写入锁。

默认自动并发为 `min(4, CPU 逻辑核数, 文件数)`。可用 `cpu_workers` 固定。单文件任务本身不会为了并行而复制模型；其多页仍可使用下面的页池。

这里使用线程而不是进程，主要因为 Office 转换和大量图像/PDF 工作会进入子进程或 C 库。纯 Python 的图像风险特征仍受 GIL 影响，不能据此宣称所有 CPU 计算都获得线性加速。

Office 转换为每次调用设置独立的 LibreOffice `UserInstallation`，避免并发进程争抢同一用户配置和后台实例。

### GPU：页级运行时池

每个 `PageRuntime` 独占一套版面模型、VLM 和轻量 OCR 子进程。同一个运行时同时只处理一页，避免模型对象和 worker 标准输入输出被交叉调用。`PageRuntimePool` 将不同文档提交的页面放到同一个池中，因此多个单页图片也能并行。

任务完成顺序可以变化，但 `parse_pages()` 按任务提交顺序返回，最终 DocumentIR 的页序和块序不受并发影响。

## 2. 显存自动准入

`gpu_workers=0` 时启用自动模式：

1. 查询加载前的物理 GPU 空闲显存；
2. 完整加载第一个运行时，包括轻量 OCR 子进程；
3. 再次查询，计算空闲显存下降量 `observed_mb`；
4. 使用 `estimate_mb = max(observed_mb, gpu_worker_floor_mb)` 作为静态占用估计；
5. 每次准备新增运行时前重新查询，只有满足下式才加载：

```text
current_free_mb >= estimate_mb + gpu_free_margin_mb
```

6. 加载后继续复测并更新估计，直到余量不足或达到 `max_gpu_workers`。

例如实测第一个运行时增加约 10 GiB 占用，余量设置为 4 GiB，则新增一个运行时前至少要有 14 GiB 空闲显存。30 GiB 空闲时允许增加；新增后只剩 9 GiB 时就停止。

`nvidia-smi` 查询是整卡视角，因此也能看到独立 OCR 子进程的占用。查询不可用或中途失败时，自动模式保留单运行时，不盲目增加。

### 为什么仍需余量

加载前后差值主要反映静态权重和常驻缓冲区，不等于推理峰值。VLM 激活、KV cache、不同尺寸区域、临时张量和分配器碎片都可能继续增加占用。`gpu_free_margin_mb` 是显式安全边界，默认 4096 MiB；实际验收时应根据最长页面和最大 `max_new_tokens` 调整。

自动扩张时如果明确出现 OOM，会保留已经加载成功的运行时并记录停止原因；其他加载异常仍然抛出，避免把模型路径错误伪装成“显存不足”。

### 固定模式

`gpu_workers=N` 直接创建 N 个运行时，不执行自动准入，供受控实验使用。固定模式意味着调用方自行承担显存风险，不应把它当成更安全的模式。

## 3. 设备编号与多 GPU 边界

默认从 `PADDLEOCR_VLM_DEVICE=gpu:N` 取得 `nvidia-smi` 查询编号。若设置了 `CUDA_VISIBLE_DEVICES`，逻辑 GPU 编号可能不同于物理编号，此时用 `PADDLEOCR_GPU_MEMORY_DEVICE` 显式指定物理编号。

当前自动准入面向“同一套运行时组件位于同一张 GPU”的部署。若版面、VLM、轻量 OCR 分属不同卡，单卡空闲差不能代表整套运行时，应使用固定模式并分别做容量实验。当前代码也不自动把运行时调度到多张卡；多卡任务可以在后续按卡分进程实现，不能在一个池里悄悄共享状态。

## 4. 生命周期与失败处理

- 首个视觉页到达前不创建模型池，纯文本任务不加载模型；
- 文件夹内所有文档共享页池，避免每个文件重复加载；
- 单文件失败会写入 `job-error.json` 并继续其他文件；
- 池关闭时先等待已提交页任务，再逐个关闭模型和 OCR 子进程；
- 自动模式只负责启动准入，不在推理中途动态增删模型。

## 5. 基准脚本继承的实验纪律

`benchmark_parser.py` 保留的是通用实验方法，不依赖旧私有管线：

- 默认一轮预热，预热不进入 warm 统计；
- 默认三轮 warm，报告中给出中位数、均值、最小值和最大值；
- 各轮共享同一组已加载模型，避免把模型加载重复算进 warm 时间；
- 每轮计时包含预处理、推理和结果写出；使用 `--build-knowledge-units` 时还包含知识单元构建与四个文件写出，口径写入报告；
- 每轮结束立即保存 `report.json` 和 `runs.jsonl`，中断后仍保留已完成数据；
- 记录输入文件/目录哈希、完整配置和核心源码 SHA-256，并保存源码快照；
- 输出目录必须为空，且不能位于输入目录内；
- 记录自动页池的显存事件和每轮前后显存快照。

建议比较 `gpu_workers=1/2/3` 时分别使用独立实验目录，保持输入、DPI、路由和生成参数一致。吞吐量提升不能仅看单页延迟，还应同时看整批 wall time、失败率、页面结果一致性和峰值显存。

## 6. 当前验证边界

无模型测试可以证明调度、顺序、配置和失败隔离逻辑，但不能证明真实模型的精度、吞吐或显存安全。真实验收至少需要：

1. 在目标 A40 上加载完整模型，检查自动报告中的实测占用是否合理；
2. 用包含普通文字、公式、表格和跨页文档的固定目录跑 `1/2/3` 个 worker；
3. 比较长文档与批量单页图片两种负载；
4. 检查页面输出一致性、OOM、子进程残留和整批吞吐；
5. 在确定余量前，不把自动 worker 上限调大。
