# 显式区域编排与文件夹批处理

## 这次新增什么

新入口：

```text
scripts/run_explicit_parser.py
```

它与原来的 `run_document_orchestrator.py`、`run_single_page.py` 并存。旧入口保留作实验对照，新入口不使用 `install_visual_routing()`，也不导入或替换 `_paddleocr_vl_*` 私有方法。

核心数据流：

```text
文件或文件夹
  → 原有 prepare_document（格式识别、Office 转换、PDF 拆页、ZIP/TAR 递归）
  → 公开 PP-DocLayoutV3 模型接口
  → 自己的矩形/多边形裁图与 PageRegion
  → 原有 VisualGate + route_visual_groups
  → 公开 PaddleOCR-VL 模型接口 / 轻量 PaddleOCR / 原生文本
  → 自己的 Block、Page、DocumentIR 组装
  → document.json + document.md + 路由和版面审计产物
```

## Windows 使用

在项目根目录执行。以下命令不加载模型，适合先检查文件遍历、LibreOffice、PDF 拆页和输出合同：

```powershell
.venv\Scripts\python.exe scripts\run_explicit_parser.py `
  --input var\incoming `
  --output var\explicit-prepare-001 `
  --config config\explicit_parser.json `
  --prepare-only
```

真实模型推理使用已经装好 PaddleOCR 3.7.0、PaddleX 3.7.2 和模型依赖的环境：

```powershell
.venv\paddleocr\Scripts\python.exe scripts\run_explicit_parser.py `
  --input var\incoming `
  --output var\explicit-full-001 `
  --config config\explicit_parser.json
```

`--input` 可以是：

- 单个 PDF、Office、图片、文本、JSON；
- 单个 ZIP/TAR；
- 一个文件夹。文件夹会递归处理其中的文件，不要求先打成 ZIP。

输出目录必须是新的空目录，避免旧结果被误当成当前运行结果。文件夹批处理复用同一个常驻运行时；纯文本任务不会为了“统一流程”而加载模型。

## 文件夹输出

假设输入为：

```text
incoming/
  合同/a.pdf
  合同/a.docx
  表格/费用.xlsx
```

输出按“相对路径＋原扩展名”隔离，因此同名的 PDF 和 DOCX 不会覆盖：

```text
explicit-full-001/
  batch-manifest.json
  documents/
    合同/a.pdf/
      manifest.json
      native/objects.json
      pages/
      page_packages/
      results/
        document.json
        document.md
        manifest.json
        routes.jsonl
        pages/0001/
          layout.json
          page_result.json
          page.md
          routes.jsonl
          assets/
    合同/a.docx/
    表格/费用.xlsx/
```

`batch-manifest.json` 记录每个文件的成功、失败或不支持状态。一个文件失败不会中止后续文件。输出目录位于输入目录内部时会被排除，不会递归扫描自己的产物；目录符号链接不跟随。

单文件模式没有 `batch-manifest.json`，直接在该文件的 `results/` 下写结果。

## DocumentIR 是主结果

`results/document.json` 现在始终是真正的 DocumentIR：

- 视觉页：`Page` 含图像尺寸、页号、图像引用和有序 `Block`；
- 每个块：含类型、bbox、可选多边形、正文、阅读顺序、来源和置信度；
- 路由证据：含识别器、风险分、原因、原生块 ID、区域裁剪图和版面元数据；
- 纯文本/JSON：也会生成一个合法的原生文本 Page，不再写空 `pages`；
- `--prepare-only`：视觉页生成带尺寸的页骨架，但不伪造识别文本。

模块二应优先消费 `document.json`。`document.md` 只是确定性的阅读导出，不应再作为知识构建的唯一输入。

## 可调参数

`config/explicit_parser.json` 集中保存策略常量。默认值保持原 `visual_layout_v1`，没有借重构之机改变实验策略。

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `gate.risk_threshold` | 0.45 | noisy-OR 风险分达到该值时升级到 VLM |
| `gate.formula_overlap_threshold` | 0.15 | 文本区域与公式框重叠达到该比例时升级 |
| `gate.orientation_angle_threshold` | 15° | 旋转角风险阈值 |
| `gate.math_score_threshold` | 0.45 | 图像数学结构特征阈值 |
| `gate.min_visual_contrast` | 0.15 | 低对比度风险阈值 |
| `gate.min_crop_side` | 12 像素 | 过小区域风险阈值 |
| `native_min_coverage` | 0.9 | 原生文本框被区域覆盖至少 90% 才允许跳过 OCR |
| `min_layout_box_side` | 6 像素 | 过滤无效微小检测框 |
| `max_new_tokens` | 4096 | 单次 VLM 区域识别生成长度上限 |

命令行可以只覆盖总风险阈值：

```powershell
... --risk-threshold 0.50
```

阈值变化必须使用新的输出目录，并作为新的实验配置记录。表格专用路由仍默认关闭，沿用原项目已有的负结果证据。

## 公开模型接口

`src/doc_parser/public_models.py` 只通过：

```python
paddlex.create_model(...)
```

创建独立的 PP-DocLayoutV3 与 PaddleOCR-VL-1.6-0.9B 模型。轻量文本识别继续复用现有 `hybrid_ocr_worker.py`。模型默认路径与原项目一致：

```text
models/PP-DocLayoutV3_safetensors
models/PaddleOCR-VL-1.6
```

环境变量沿用 `PADDLEOCR_VLM_DEVICE`、`PADDLEOCR_DEVICE` 等配置；版面设备也可用 `PADDLEOCR_LAYOUT_DEVICE` 单独指定。

## 与旧版的差异和验收边界

1. 新管线不调用第三方私有的重叠框过滤、相邻块合并和结果组装函数；目前只做边界裁剪、微小框过滤和显式区域排序。因此输出不承诺与旧版逐字相同。
2. 表格原始结构串会保存在 IR 中；若模型返回 OTSL 而新版没有转换器，Markdown 会将其放在 `<pre>` 中原样保留，不伪装成 HTML 表格。
3. 当前新增的是 CLI/库入口，尚未替换 `serve_api.py` 的线上常驻服务路径。
4. 当前环境没有模型权重，未做真实 PP-DocLayoutV3/PaddleOCR-VL 推理和精度对比。公开接口按项目固定的 PaddleOCR 3.7.0、PaddleX 3.7.2 源码核对，仍需 A40 或已有 PaddleOCR 环境验收。
5. 原管线保留，可在同一批页面上做新旧对照。建议先比较版面框数、块顺序、文本编辑距离、表格结构、公式和运行时间，再决定是否替换生产入口。
