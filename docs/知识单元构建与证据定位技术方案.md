# 知识单元构建与证据定位技术方案

## 1. 目标与实现边界

本模块接收解析阶段产生的 `DocumentIR`，把“页—块”形式的解析结果转换成后续检索、版本管理、结构化压缩和问答都能稳定引用的知识单元。

本模块完成两件事：

1. **元素位置表**：记录每个单元对应哪些原始块，以及页码、框坐标、阅读顺序、资产路径和块内字符区间。
2. **知识单元构建**：按标题层级、块类型、题注邻接和长度特征切分单元，建立语义父子树，并生成确定性的上下文前缀。

实现位于 `src/doc_parser/knowledge_units.py`，不调用模型、不访问网络。本模块不做向量化、BM25、重排、密级推断、字段抽取和摘要；这些属于后续模块。正文不被 LLM 改写，避免知识构建阶段引入不可复现的内容变化。

## 2. 输入、输出与入口

### 2.1 输入

正文输入为 `results/document.json`，反序列化为 `DocumentIR` 后必须通过 `DocumentIR.validate()`。

| 层级 | 主要字段 | 用途 |
|---|---|---|
| DocumentIR | `document_id`、`content_hash`、`title`、`metadata` | 文档身份、源版本、标题前缀、解析管线 |
| Page | `page_id`、`page_no`、`width`、`height` | 页级定位和坐标解释 |
| Block | `block_id`、`block_type`、`bbox`、`polygon`、`text`、`reading_order`、`confidence` | 切分、排序、定位和质量复核 |
| Block.source | `engine`、`raw_page`、`raw_block_id`、`raw_path` | 解析来源追踪 |
| Block.metadata | `raw_label`、`heading_level`、`asset_path` 等 | 标题级别、题注识别和资产关联 |

本模块不改写原始坐标。`ElementLocation` 同时保存页宽和页高，后续展示层可以另行归一化，但不能覆盖原始像素框。

### 2.2 输出

```text
knowledge-units/
  knowledge-units.jsonl
  element-locations.jsonl
  document-tree.json
  manifest.json
```

四个文件均为 UTF-8 JSON/JSONL，不要求数据库。PostgreSQL、Milvus 等写入属于后续集成层。

### 2.3 两种运行方式

主链追加构建：

```python
run_path(input_path, output, build_knowledge_units=True, knowledge_unit_config=KnowledgeUnitConfig())
```

已有 IR 离线构建：

```python
build_knowledge_units_from_json("document.json", "knowledge-units-output", config=KnowledgeUnitConfig())
```

命令行分别使用 `scripts/run_parser.py --build-knowledge-units` 和 `scripts/build_knowledge_units.py`。后者支持单文件、结果目录及递归批处理。

## 3. 核心数据模型

### 3.1 KnowledgeUnit

```json
{
  "unit_id": "ku_...",
  "document_id": "doc_...",
  "source_content_hash": "sha256...",
  "parent_unit_id": null,
  "child_unit_ids": [],
  "unit_type": "document_title|section|paragraph|table|figure|formula|list",
  "heading_path": ["企业手册", "第一章", "1.1 系统结构"],
  "text": "用于检索的单元正文",
  "context_prefix": "企业手册 > 第一章 > 1.1 系统结构",
  "token_count": 0,
  "tokenizer_name": "unicode-word-v1",
  "block_ids": ["doc_p0001_b0000"],
  "page_start": 1,
  "page_end": 1,
  "reading_order_start": 0,
  "reading_order_end": 2,
  "asset_paths": [],
  "content_hash": "sha256...",
  "parser_pipeline": "document-ir-v2",
  "builder_version": "knowledge-unit-v1",
  "metadata": {
    "split_reason": "feature_group",
    "source_confidence_min": 0.91,
    "needs_review": false,
    "is_container": false,
    "indexable": true,
    "shared_block_split": false
  }
}
```

`document_title` 和 `section` 是容器，`indexable=False`；它们保留标题正文和标题块位置，但不交给混合检索做正文向量索引。普通正文单元可索引。

`context_prefix` 是检索时可拼在正文前的上下文，不等于正文，也不进入位置表字符偏移。`token_count` 使用 `unicode-word-v1`：CJK 单字、拉丁词、数字和其他非空白符号各作为一个本地长度单位。它只用于可复现的切分，不声称等于任何向量模型 tokenizer。

### 3.2 ElementLocation

```json
{
  "location_id": "loc_...",
  "document_id": "doc_...",
  "unit_id": "ku_...",
  "block_id": "doc_p0001_b0000",
  "page_id": "doc_p0001",
  "page_no": 1,
  "bbox": [10.0, 20.0, 500.0, 120.0],
  "polygon": null,
  "page_width": 1240.0,
  "page_height": 1754.0,
  "reading_order": 0,
  "text_start": 0,
  "text_end": 42,
  "source": {},
  "asset_path": null,
  "evidence_hash": "sha256..."
}
```

`text_start/text_end` 是相对于原始 `Block.text` 的 Python 字符切片区间，采用左闭右开。`evidence_hash` 对 `Block.text[text_start:text_end]` 计算 SHA-256，因此长块拆分后仍能验证每段证据。

一个单元可以对应多条位置记录。一个长块也可通过互不重叠的字符区间属于多个单元，避免复制正文导致重复召回。

### 3.3 文档树

```text
Document
└── Section 容器
    └── KnowledgeUnit
        └── ElementLocation
```

页面是定位维度，不是语义父节点。标题栈跨页保留，因此同一章节可以包含后续页正文；普通段落是否跨页合并是另一条更严格的规则。

## 4. 构建算法

### 4.1 校验与稳定排序

1. 校验 DocumentIR；源块 ID 必须在整份文档内唯一。
2. 按 `page_no`、`reading_order` 排序；缺失阅读顺序时使用原始块序，并计入 `missing_reading_order`。
3. 默认忽略页眉、页脚、页码及其图片，忽略原因写入 manifest。
4. 普通空文本块记为 `empty_text`；空标题记为 `empty_heading`；无文字的表格、图片、公式仍保留。

### 4.2 标题栈

- `document_title` 级别为 0，`section_heading` 从 `heading_level` 或 `level` 读取正整数级别。
- 新标题级别为 `L` 时，弹出所有级别大于等于 `L` 的旧标题。
- 当前标题压栈，其容器 ID 成为后续正文的 `parent_unit_id`。
- 缺失或非法级别退回 1，并记录 `heading_level_defaulted` 或 `invalid_heading_level`。
- 标题跳级保留结构，同时记录 `heading_level_jump`，不擅自重排文档。

### 4.3 特征分组与题注

| 块类型 | 实现策略 |
|---|---|
| 表格 | 原子单元，不拆表体；相邻题注并入正文与 `metadata.caption` |
| 图片/图表 | 原子单元，保存资产路径；相邻题注并入 |
| 独立公式 | 原子单元，保留章节上下文 |
| 普通段落 | 同节、同页、相邻、同类型且长度合适时合并 |
| 列表 | 采用同样的同页分组规则；超长时按通用自然边界/硬切规则处理 |
| 页眉页脚/页码 | 默认忽略，但 DocumentIR 原块不删除 |

题注只并入同页、同章节且直接相邻的表格或图片。找不到目标时退化为普通段落。首版不猜测跨页续段，也不做列表项语法解析。

### 4.4 长度约束

默认配置位于 `config/knowledge_units.json`：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `target_tokens` | 600 | 普通正文合并目标 |
| `min_tokens` | 120 | 短单元合并判断阈值 |
| `max_tokens` | 1000 | 普通正文长度上限 |
| `prefix_max_chars` | 240 | 上下文前缀最大字符数 |
| `review_confidence` | 0.6 | 低于该源置信度的单元需复核 |
| `ignored_raw_labels` | 页眉页脚等 | 显式忽略规则 |

处理顺序是“先保持原子边界，再处理长度”。超长段落或列表优先在句号、问号、分号、换行等边界切分；找不到边界才按上限硬切，并标记 `split_reason=length_fallback`。表格、图片和公式不进入该切分逻辑。

超长块的各部分是同章节下的同级正文单元，首版不额外制造一个重复保存全文的父容器。

### 4.5 上下文前缀

前缀由可信字段拼接：

```text
文档标题 > 一级标题 > 二级标题 > …
```

文档标题与路径中的重复项会去掉。前缀超长时优先保留文档标题和最近两级标题；题注保存在单元正文和元数据中，不再重复塞入前缀。

## 5. ID、哈希与可复现性

- `unit_id`：由文档 ID、父容器、标题路径、类型、容器标志及有序 `block_id:text_start:text_end` 生成。
- `location_id`：由 `unit_id + block_id + text_start/text_end` 生成。
- `content_hash`：对单元正文计算 SHA-256。
- `evidence_hash`：对原块对应字符区间计算 SHA-256。
- `source_content_hash`：沿用解析输入文件哈希，供版本与增量管理关联源版本。
- `document_ir_sha256`：对规范化 DocumentIR 字典计算 SHA-256。
- `builder_version` 和完整配置进入 manifest；版本与增量管理可据其形成加工版本键。

输出不写入运行时间。相同 DocumentIR 与相同配置重复构建，四个文件必须逐字节一致。输出目录若非空则拒绝写入，避免混合两次产物。

## 6. 一致性硬校验

`build_knowledge_units()` 在返回前自动调用 `validate_knowledge_units()`，至少检查：

1. 单元和位置 ID 唯一，源块 ID 在文档内唯一；
2. 单元文档身份、正文哈希和 token 数可重算；
3. 父子关系双向一致，父节点为容器，语义树无环且与单元关系一致；
4. 每条位置都回指真实单元、真实块和真实页；
5. 字符区间合法，证据哈希与原块切片一致；
6. 框、`polygon`、页尺寸与 DocumentIR 一致，框不得越出页面；
7. 单元页码和阅读顺序范围与位置记录一致；
8. 同一源块的多个字符区间不得重叠；
9. 每个源块必须“被映射”或“有唯一明确忽略原因”，二者不能同时发生。

资产路径会被保留，但知识单元构建器不知道消费方的工作目录，因此不在核心层擅自解析或检查资产文件是否存在。部署集成层应以文档输出根目录解析这些相对路径。

manifest 还记录源块/映射块/忽略块数、容器/正文单元数、位置数、题注合并数、长度切分数、需复核数、长度最小/最大/均值、覆盖率和诊断。这些用于回归，不等同于检索或问答质量。

## 7. 与其他模块的接口

### 混合检索

只索引 `metadata.indexable=True` 的单元。混合检索可分别使用 `text` 与 `context_prefix`，返回结果携带 `unit_id`，问答层再通过位置表获得页码、块 ID 和框。

### 版本与增量管理

以源文件哈希、解析管线版本、知识单元构建器版本和配置内容区分加工版本。仅知识单元配置变化时可复用 DocumentIR，无需重新 OCR。

### 结构化压缩

抽取和摘要保留 `unit_id`，重要结论继续下钻到 `ElementLocation`。摘要不得覆盖原始单元正文。

### 质量评测

自动检查引用是否落到正确单元、页和框，并对照不同切分参数的召回、重复率、上下文完整性和延迟。开发集与最终测试集必须分离。

## 8. 当前边界与验收

已实现并测试标题树、原子表格/图片/公式、题注合并、同页分组、自然/硬切、无重叠字符区间、低置信度复核、严格引用校验、确定性输出、主链接入和批量失败隔离。

当前明确边界：

- 标题质量取决于 DocumentIR；原生整段文本若尚未识别标题，知识单元构建器不会凭空编造层级。
- 不做跨页续段猜测，不做语义模型重排，不做列表项语法分析。
- 默认切分参数仍需通过质量评测中的检索任务对照，而不是仅凭单元长度分布决定。
- 无模型测试证明知识单元构建与调度逻辑，不证明真实 OCR 精度、吞吐或显存安全；真实模型仍须在 A40 或已有 PaddleOCR 环境验收。
